# 0.1.5 验证记录：workspace 路径与预览切换

本文件记录 0.1.5 的实测证据，明确区分「已实测」与「仍需 GUI 手点」。

## 环境

- dsh：`0.2.1-rc.5`（Windows 桌面版自带 CLI：`resources/runtime/cli/bin/dsh.cmd`）
- 插件：本仓库 `lib/`（与随包提交的产物同一份），通过 `--patch` 的 `file://` overlay 加载
- `DSH_HOME`：临时目录 `_verify/home`；`dsh web --no-open --port 0`
- overlay 配置：`mode: auto`、`priority: builtin`、`rememberChoice: true`、`debug: true`、
  `workspaceRoot: ''`（留空，验证服务端取根逻辑）
- 工作区：`_verify/ws`（`docs/plain.md`、`docs/中文 空格.md`、`src/main.ts`）
- 工作区外：`_verify/outside/secret.md`

启动输出：

```
dsh web: http://127.0.0.1:64998/?token=…
```

## 真实输入（debug 诊断）

`GET /docu-preview/api/diagnostics?address=…` 回显（已实测）：

```json
{
  "outcome": "resolved",
  "address": "dsh-resource://file/session/session-11111111-1111-4111-8111-111111111111/docs/中文 空格.md",
  "scope": "session",
  "sessionId": "session-11111111-1111-4111-8111-111111111111",
  "requested": "docs/中文 空格.md",
  "roots": ["D:\\Users\\zheng.li\\Documents\\Trae-CN\\temp_20261102_01\\_verify\\ws"],
  "trace": [{ "candidate": "…\\_verify\\ws\\docs\\中文 空格.md", "contained": true, … }]
}
```

说明：本次 0.1.5 验证用的是**合成的持久化 session**（`session.header.cwd = …\_verify\ws`）；
dsh 的 `sessions.get(id)` 只返回**已激活**的 session（`SessionStore.store` 是内存 Map），
所以这个离线 session 没有被 UI 激活时，解析走的是第二优先级
`sandboxPolicy.workspaceRoot`（本次 boot 的 cwd 就是 `_verify/ws`）。
`session.header.cwd` 这条第一优先级由单测
[tests/host.spec.ts](../tests/host.spec.ts) 的 `uses the session workspace for a session address`
固定；真实 GUI 里 session 一定是激活状态，会命中该分支。

## HTTP 结果（全部已实测）

| 用例 | 地址形态 | 结果 |
| --- | --- | --- |
| viewer 静态页 | `GET /docu-preview/viewer/index.html` | **200** |
| 配置 | `GET /api/options` | **200** `{"mode":"auto","priority":"builtin","rememberChoice":true}` |
| 中文 + 空格（session 相对） | `dsh-resource://file/session/<sid>/docs/中文 空格.md` | **200**，`path: docs/中文 空格.md` |
| 读文件 | `GET /api/file?token=…` | **200**，返回 `# 中文 空格…` 正文 |
| 反斜杠相对路径 | `dsh-resource://file/session/<sid>/docs%5Cplain.md` | **200**，归一化为 `docs/plain.md` |
| 盘符 `%3A` 编码 | `dsh-resource://file/absolute/D%3A/Users/…/_verify/ws/docs/plain.md` | **200** |
| 绝对路径（workspace 内） | `dsh-resource://file/absolute/D:/…/_verify/ws/docs/plain.md` | **200** |
| 越权（workspace 外） | `dsh-resource://file/absolute/D:/…/_verify/outside/secret.md` | **403** `outside_workspace` |
| 诊断越权 | 同上 | `outcome: "outside"` |
| 数字段穿越 | `dsh-resource://file/session/<sid>/docs/../outside/secret.md` | **404**（仍在 workspace 内，目标不存在） |

## 根因对照

0.1.4：`workspaceRoot` 为空 → `roots()` 回退 `process.cwd()`。桌面版 dsh 的进程 cwd 不是会话工作区，
所以 `docs/中文 空格.md` 被拼到错误目录，`realpath` 全部失败 → `no such file in the workspace`。

0.1.5：按地址作用域取根（`session.header.cwd` → `sandboxPolicy.workspaceRoot` → 配置 → cwd），
并对「归一化路径 + realpath」双重做包含性判断；realpath 失败回退归一化路径，盘符大小写不敏感；
越权仍是 403。上面的 200/403 表就是修复后的实测结果。

等价性依据：插件在浏览器侧只是把 `dsh-resource://` 地址 POST 给同一个宿主 handler，

（`file/session/<sid>/<相对路径>` 与 `file/absolute/<绝对路径>`）。
